# COGS model — 60,000 calls/month

**Date:** 2026-07-23 · **Currency:** USD · **Region:** Sydney (`australia-southeast1` / `ap-southeast-2`)
**Pricing retrieved:** 22–23 July 2026 from vendor pricing pages (sources at the end).

> Supersedes the pilot figures in `2026-07-19-cogs-model.md`, which modelled 500–1,200 dials/day.

## 1. Scenario

| Input | Value |
|---|---|
| Total dials / month | 60,000 |
| Purely human-dialed | 20,000 |
| AI-dialed | 40,000 |
| Connection rate (reached a live human) | 10% |
| AI talk time before transfer | 1.5 min |
| Peak concurrency | 5–8 channels |

### Assumptions I had to add (not specified — **change these to re-model**)

| Assumption | Value | Why it matters |
|---|---|---|
| **Mobile / landline mix** | **80 / 20** | **The single biggest cost driver** — see §5 |
| Voicemail rate | 20% of dials | Voicemail *answers*, so telco bills it |
| Human talk time (connected) | 4.0 min | Drives both telco and channel count |
| AI connects that transfer to a human | 30% | 1,200 transfers/month |
| AI voicemail handling | 0.30 min | AMD + voicemail drop |
| Human voicemail handling | 0.20 min | Agent hears machine, hangs up |
| Working days / hours | 22 days × 9 h | Concurrency check |
| Unanswered calls | **not billed** | Twilio bills outbound on answer |

### Derived call minutes

| Stream | Minutes |
|---|---|
| AI conversation (4,000 × 1.5) | 6,000 |
| Transferred human leg (1,200 × 4.0) | 4,800 |
| AI voicemail handling (8,000 × 0.3) | 2,400 |
| Human-dialed talk (2,000 × 4.0) | 8,000 |
| Human-dialed voicemail (4,000 × 0.2) | 800 |
| **Total billable telco minutes** | **22,000** |

**Concurrency cross-check:** 22,000 talk-min ÷ 11,880 working-min = 1.85 average, plus ~2.1 channels
tied up ringing (5 dials/min × 25 s) ⇒ **~4 average, 6–8 peak**. ✅ Consistent with the stated 5–8, so
infra below is sized for peak-8.

## 3. Where the money actually goes

```
Telco + DIDs   ████████████████████████████████  65.3%   $1,383
Infra (VM/DB)  ███████                           13.8%   $  292
LiveKit Cloud  ██████                            12.2%   $  259
TTS (Aura-2)   ███                                6.2%   $  132
STT (Nova-3)   █                                  1.5%   $   33
LLM            ▌                                  0.3%   $    6
```

**Two conclusions:**

1. **Telco dominates.** Every platform-side optimisation combined cannot move the number as much as
   the carrier rate can. This confirms the earlier COGS doc's conclusion — now with the ratio measured
   rather than assumed.
2. **The LLM is free, effectively.** At $5.82/month, model choice is an accuracy decision, not a cost
   one. Groq Llama 3.1 8B would save $3.22/month — not a reason to pick it. **TTS costs 23× the LLM**;
   if you want to optimise AI spend, that is the line to attack.

## 4. The big lever: carrier rate

Twilio's AU **mobile** termination is **$0.0710/min** — retail pricing. Australian wholesale carriers
routinely quote a fraction of that for committed volume.

| Mobile rate | Telco cost | Total COGS | Saving vs Twilio |
|---|---|---|---|
| $0.0710 (Twilio retail) | $1,343 | $2,116 | — |
| $0.040 | $806 | $1,579 | **−$537/mo** |
| $0.020 | $454 | $1,227 | **−$889/mo** |
| $0.010 | $278 | $1,051 | **−$1,065/mo** |

**A wholesale carrier deal is worth up to ~$1,000/month at this volume — roughly 50% of total COGS.**
Given you already have a carrier relationship, this is the highest-leverage commercial action
available, and it dwarfs every engineering optimisation in this document.

## 5. Sensitivity

### Mobile/landline mix (the assumption I had to invent)

| Mix | Telco | Total COGS |
|---|---|---|
| 100% mobile | $1,562 | $2,335 |
| **80/20 (modelled)** | **$1,343** | **$2,116** |
| 50/50 | $1,014 | $1,787 |
| 100% landline | $466 | $1,239 |

**Swing: ~$1,100/month.** If your lists are mobile-heavy, the top row is your real number. Worth
measuring the actual mix in your lead data before committing to a price to the client.

### Other sensitivities

| Change | Effect |
|---|---|
| Connect rate 10% → 15% | +~$390/mo (more talk minutes — *good* spend) |
| Human talk 4 → 6 min | +~$390/mo |
| 1-year committed-use discount on both VMs | **−$77/mo** |
| Self-host LiveKit instead of Cloud | −$120/mo, +ops burden (see §6) |
| Aura-2 → Aura-1 TTS | −$66/mo (quality trade-off) |

## 6. LiveKit: Cloud vs self-hosted

| | LiveKit Cloud (Ship) | Self-hosted on GCP |
|---|---|---|
| Software | — | Apache-2.0, **free** |
| Cost | **$259/mo** | ~$139 VM + ~$5 egress ≈ **$144/mo** |
| Includes | SFU, SIP bridge, TURN, egress/recording, SLA 99.99% | You run all of it |
| Ops burden | None | SIP bridge uptime, TURN, scaling, upgrades |

**Recommendation: stay on LiveKit Cloud.** The $115/month saving does not cover the engineering time
to own a SIP bridge and TURN infrastructure, and at 5–8 concurrent channels you are nowhere near the
scale where self-hosting pays. Revisit past ~100 concurrent channels.

LiveKit's own benchmark recommends a `c2-standard-16` as a production *minimum* for self-hosting —
far more machine than this workload needs, which is itself a signal that Cloud is right at this size.

## 7. Growth

Costs are ~85% variable, so they scale close to linearly:

| Volume | Est. total COGS | Notes |
|---|---|---|
| 60k dials/mo | $2,116 | as modelled |
| 120k dials/mo | ~$3,900 | may need M20 Atlas (+$109) and a 2nd worker VM |
| 240k dials/mo | ~$7,500 | LiveKit **Scale** plan ($500 base, cheaper units); Redis + multi-instance API required first |

**Blocking dependency:** the API is single-instance today (in-process concurrency counters, transfer
offers, RR cursor, socket registry, CLI rotation, analytics cache). Redis is required *before* volume
growth, not after — see `2026-07-23-progress-and-next-steps.md` §P1.

## 8. What is NOT in this model

- **Agent labour** — the BPO's cost, not platform COGS.
- **The `SCREENED` outcome.** Call-screening services (e.g. Telstra Call Guardian) answer the call —
  so you pay telco while a prompt plays on a call that may never reach a human. Not yet measurable
  because the outcome doesn't exist in the schema; add it before it hides inside connect rate.
- **Number remediation services** — likely needed once DIDs start getting labelled; pricing is
  contact-sales.
- **Twilio volume discounts** — not published; assume retail until negotiated.
- **Deepgram Growth tier** — ~20% off STT/TTS for prepaid annual commit, i.e. ~$33/mo saving. Minor.
- Dev/staging environments, monitoring/APM, backups beyond Atlas defaults, support plans.
